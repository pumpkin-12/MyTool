## 产出：Tauri 桌面端迁移方案

交付物：`docs/tauri-迁移方案.html`（自包含 HTML，浅色主题，可打印）。

核心结论：**不是重写**。现有代码已预埋 Tauri 分支（`AppStore` 三后端探测 + `window.__TAURI__.core.invoke` + `isDesktop` 分流 Mermaid 加载），缺的只是 Rust 侧工程与配置。

### 技术选型（核准于 2026-09-11）
- 用 Tauri **2 稳定线**：tauri crate 2.11.5 / tauri-cli 2.11.4 / @tauri-apps/api 2.11.1。
- **不用 Tauri 3**：CEF 后端仍是 early alpha（tauri-cef-v3.0.0-alpha.22），对只面向 Windows 的项目零收益。
- 不引入 Vite/打包器，保持单文件零构建。

### 四个阻塞项（已写进方案）
- **B1** `vendor/mermaid.min.js` 缺失 → 需补 mermaid 11 的 **UMD** 构建（`viaLocal()` 读 `window.mermaid` 全局；CDN 那路才是 ESM）。
- **B2** Rust 侧 `store_read` / `store_write` 不存在。
- **B3** 必须 `app.withGlobalTauri: true`，否则 `window.__TAURI__` 不存在 → 永远走 localStorage → 数据存 WebView 缓存里随时丢。
- **B4** 必须 `app.windows[].dragDropEnabled: false`。

### 高危项
- **H1** 5 处导出走 `<a download>` + blob/data URL，WebView2 下行为不可控 → 改原生 save_file。
- **H2** `persist()` 每次 set 全量写盘且无串行化 → invoke 完成顺序无保证，有后写覆盖先写的竞态。
- **H3** native 分支 `AppStore.set` 恒返回 true → 画板「保存失败」提示永不触发。
- **H4** 画板图片 base64 内联进 `shapes`，随 JSON 全量 stringify。
- **H5** 浏览器 → 桌面端无数据迁移通道（仅画板有 exportJSON）。

### 关键技术坑（已用官方文档核实）
1. **`dragDropEnabled` 与 HTML5 拖放互斥**——Windows 上 Tauri 用原生 OLE 拖放目标，会**吞掉** WebView 的 `drop` 事件（表现为禁止光标，`dragstart` 有但 `dragover`/`drop` 不触发）。macOS/Linux 无此问题。本项目的**首页卡片拖拽排序**和**画板拖入图片**都依赖 HTML5 DnD，所以必须设 `false`。且该属性只在 `tauri.conf.json` 声明窗口时可靠生效，写在 Rust window builder 里会被静默忽略。
2. **IPC 传二进制不要用 `Vec<u8>`**——serde_json 会把每个字节展开成 `255,` 形式，5MB PNG 的 payload 可膨胀到十几 MB。改用 **base64 字符串 + Rust `base64` crate 解码**。
3. **IPC 参数命名**：前端 camelCase ↔ Rust snake_case 自动转换，两头都写 snake_case 反而报缺参数。
4. **权限系统只管插件/核心命令**——自定义命令（`generate_handler!` 注册的）不受 capability 管辖，`core:default` 就够，不必给自定义命令加权限。
5. `csp: null` 先不收紧：index.html 有巨型内联 `<script>` 和大量内联 style，收紧需 `'unsafe-inline'` + 放行 `cdn.jsdelivr.net`，属独立任务。
6. `productName` 用 ASCII（NSIS 输出文件名会用到），中文显示用窗口 `title`。
7. `tauri-plugin-dialog` 的 `FilePath::into_path(self) -> Result<PathBuf, Error>`；`blocking_save_file()` 不能在主线程调用 → 命令声明为 `async fn`。
