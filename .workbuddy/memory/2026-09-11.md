### 关键技术坑（已用官方文档核实）
1. **`dragDropEnabled` 与 HTML5 拖放互斥**——Windows 上 Tauri 用原生 OLE 拖放目标，会**吞掉** WebView 的 `drop` 事件（表现为禁止光标，`dragstart` 有但 `dragover`/`drop` 不触发）。macOS/Linux 无此问题。本项目的**首页卡片拖拽排序**和**画板拖入图片**都依赖 HTML5 DnD，所以必须设 `false`。且该属性只在 `tauri.conf.json` 声明窗口时可靠生效，写在 Rust window builder 里会被静默忽略。
2. **IPC 传二进制不要用 `Vec<u8>`**——serde_json 会把每个字节展开成 `255,` 形式，5MB PNG 的 payload 可膨胀到十几 MB。改用 **base64 字符串 + Rust `base64` crate 解码**。
3. **IPC 参数命名**：前端 camelCase ↔ Rust snake_case 自动转换，两头都写 snake_case 反而报缺参数。
4. **权限系统只管插件/核心命令**——自定义命令（`generate_handler!` 注册的）不受 capability 管辖，`core:default` 就够，不必给自定义命令加权限。
5. `csp: null` 先不收紧：index.html 有巨型内联 `<script>` 和大量内联 style，收紧需 `'unsafe-inline'` + 放行 `cdn.jsdelivr.net`，属独立任务。
6. `productName` 用 ASCII（NSIS 输出文件名会用到），中文显示用窗口 `title`。
7. `tauri-plugin-dialog` 的 `FilePath::into_path(self) -> Result<PathBuf, Error>`；`blocking_save_file()` 不能在主线程调用 → 命令声明为 `async fn`。

### 关键技术产出与实测结论
1. **mermaid 离线文件**：`https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js`（3,572,661 字节）。
   - 它**不是 UMD**，是 esbuild 的 IIFE，但**最后一行**是 `globalThis["mermaid"] = globalThis.__esbuild_esm_mermaid_nm["mermaid"].default;` → 会挂到 `window.mermaid`，所以 **`viaLocal()` 一行都不用改**。
   - `chunkRefs=0`、`dynamicImports=0`，单文件自包含，无懒加载拆分。
   - **教训**：不要靠 grep 字面量 `window.mermaid` 判断——它用的是 `globalThis.mermaid`。要点是**实际在 Node 的 `vm` 里跑一遍**看全局对象上有什么（`tools/` 下没有留这个探针，方法记在这里）。
2. **Rust 侧三条命令**（`src-tauri/src/lib.rs`）：`store_read` / `store_write` / `save_file`。
   - `store_write`：先 `serde_json::from_str` 校验合法性 → 轮转备份 → 临时文件 + `fs::rename` 原子替换。
   - **额外加固（方案外）**：存档轮转 `store.json.1/.2/.3`，**30 分钟节流**（`Mutex<Option<Instant>>` 放 Tauri state）。不节流的话画板 400ms 防抖会反复复制几 MB 文件。
   - `save_file`：**async fn**（`blocking_save_file()` 不能跑主线程）；收 **base64 字符串**而非 `Vec<u8>`（字节数组走 JSON IPC 会把每个字节展开成 `255,`，体积爆炸）；用 `base64::engine::general_purpose::STANDARD`。
   - IPC 参数命名：前端 camelCase ↔ Rust snake_case **自动转换**，两头都写 snake_case 会报缺参数。
3. **前端补丁 A（H2/H3）**：`AppStore.persist()` 改 Promise 链串行化；新增 `flush()` / `lastError()`；`set()` 返回值从恒定 true 改为真实写盘结果（有一次性延迟）。
4. **前端补丁 B（H1）**：新增全局 `saveBlob()` / `blobToBase64()`，5 处导出全改道原生另存为；删掉 `downloadBlob()` 与 `download(url,name)`。画板 `exportPNG` 从 `toDataURL` 改 `toBlob`。

## ⚠️ 我漏做的一件事：单实例
方案第 1 档里我列了「单实例（第二次启动聚焦已有窗口）」，但**实现时漏了**，`lib.rs` 里没有 `tauri-plugin-single-instance`。

后果是真实的：`AppStore` 启动时把**整个存档读进内存**，之后每次 `set` 都全量写回。所以开两个实例（比如装好的版本 + 便携版同时开着）会互相覆盖——后写的那份把另一个实例的所有改动抹掉。这是**数据丢失风险**，不是体验问题。

修法很小（约 5 行）：

```toml
# Cargo.toml
tauri-plugin-single-instance = "2"
```
```rust
// lib.rs run() 里，必须放在最前面
.plugin(tauri_plugin_single_instance::init(|app, _argv, _cwd| {
    if let Some(w) = app.get_webview_window("main") {
        let _ = w.unminimize();
        let _ = w.set_focus();
    }
}))
```

注意顺序：`.plugin(tauri_plugin_single_instance::init(...))` 要在 `.plugin(tauri_plugin_dialog::init())` **之前**注册才可靠。

**推荐 C**：UI 工作量全保住（BankPanel 18 KB / QuizPanel 12 KB 是真实投入）；Java 逻辑（QuizService 15.9 + QuestionService 5.5 + StatsService 4 + WrongQuestionService 1.9 ≈ 28 KB）翻译成 JS 是一次性成本，且 **Java 版留着当规格说明**，`QuizServiceTest.java`(31 KB) 直接就是验收用例；体积只 +1.89 MB，和已接受的 mermaid 3.5 MB 同量级。

**一个要用户点头的破例**：工具箱硬约定是「不引入打包器」，方案 C 会让仓库出现 Vue 构建产物。建议折中——源码留 quiz-app 仓库，工具箱只收 dist 当 vendor 资源（和 `mermaid.min.js` 同级），不在工具箱里跑 npm。

### 已知要提前处理的技术点
- **存档体量**：工具箱每次保存都全量 stringify 整个存档。题库上千题会长得很快，**建议 quiz 数据拆独立文件**——正好和工具箱第 2 档「存档按 key 拆分」合并做。
- **iframe 与父页同源**（都是 `tauri://localhost`）→ **共享 localStorage**。本地适配层要么统一走 AppStore，要么加独立 key 前缀，否则污染 `toolbox:*` 体系。
- 构建时关掉 `productionSourceMap`，否则多拷 6.8 MB 无用文件。
- 保留 `request.js` 的 axios 分支，这样 quiz-app 仍能前后端分离跑 `npm run serve` 用浏览器调，两边共用一个界面代码库。
