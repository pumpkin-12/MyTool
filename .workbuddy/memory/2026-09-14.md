## 第二档 3.10：mermaid 按需加载 + 离开释放（已完成，commit `dcc8d4a`）

用户选"先做 3.10"。改动全在 `web/index.html`（前端，不动 Rust、不引打包器）：

**原问题**：`index.html:3439` 进 Mermaid 页立刻 `loadLib()` 注入 3.41 MB 的 mermaid.min.js；
`dispose()` 只清定时器，`lib` 变量与注入的 `<script>` 都不释放 → 进过一次就常驻 renderer 60~100 MB。

**改法**：
1. `loadScript`：**在 `appendChild` 之前**登记到模块级 `Set` `injectedScripts`（抽出 `dropInjected()` 统一移除路径）
2. `viaLocal` / `loadLib`：若 `disposed` 已在加载期间置位，则 `dropInjected` 且**不持有 lib 引用**（reject）
3. `dispose`：`lib = null` / `loading = null` / `libErr = null` / `window.mermaid = null` + 清空 `injectedScripts`

**踩到的真实缺陷（重要教训）**：最初把 `injectedScript = s` 放在 `onload` 回调里赋值。
→ **"脚本还在加载中就切走页面"**时 onload 尚未触发，`injectedScript` 仍是旧值/null，那个 `<script>` 永久残留 head。
被专项测试 `[6] 加载中切走` 抓出。**修法：登记必须早于 `appendChild`，不能等 onload。**

**验证**：
- 内联脚本语法 0 错误
- `verify-appstore` 35/0、`verify-quizcore` 87/0（与改动前基线一致）
- 新增 **`tools/verify-mermaid-release.js`（23/0）**，抽模块 + 极简 DOM 模拟，覆盖
  dispose 释放 / 切走再切回 / 加载中切走 三条易错路径
  （写测试时也踩了 mock 坑：`appendChild` 必须设 `parentNode`，否则 `removeChild` 找不到 → 假 FAIL）

**预期效果**：不用 Mermaid 时 renderer 从 69 MB 降到约 20~35 MB。**待用户 `tauri dev` 真机确认。**

`index.html` 4909 → 4933 行，4905 → 226.9 KB。
