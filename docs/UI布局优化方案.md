# UI 布局优化方案

> 目标：`D:\Ai-file\MyTool` 前端（`web/index.html` + `web/js/`）
> 性质：**先给方案、不动代码**。方案里的数字都是实测的，不是估的。
> 一句话结论：**问题分两层 —— 一层是"没有设计体系"（散），一层是"家具压死内容"（挤）。
> 散的修起来便宜、收益广；挤的只影响实习日志一个页面，但影响最大。**

---

## 0. 先说结论

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| 🔴 最高 | **实习日志的信息层级重排**：主操作上移 + 图表默认折叠 | 实测**要滚 1.8 屏才看到第一条日志**，主操作「+ 新日志」也在第一屏之外 |
| 🔴 高 | **抽设计 token**（间距 / 字号 / 圆角 / 阴影 / 焦点环） | padding 用了 **41 种**取值、margin **34 种**、font-size **14 种** —— 改一处样式要读全文 |
| 🟡 中 | 统一面板类 `.panel` + 统一焦点环 | 同类东西在三个工具里长得不一样（`.card` / `.note-card` / `.df-sec`） |
| 🟢 低 | 响应式（现在只有 1 处 `@media`）· 动效 · a11y | 桌面单窗口自用，收益没那么急 |

## 1. 现状体检（全是实测数字）

### 1.1 规模

| 项 | 值 |
|---|---|
| `web/index.html` | **529 行**，其中内联 CSS **503 行（95%）** |
| CSS 规则条数 | 350 条 |
| `:root` 设计变量 | **只有 8 个**（bg/surface/text/muted/border/accent/ok/err） |
| 各工具模块行数 | sketch 1788 · internlog 1535 · quiz 1273 · defect 963 |

`:root` 那 8 个变量全是**颜色**，**没有一个是间距、字号、圆角、阴影** —— 也就是说
"设计体系"只覆盖了配色，几何部分全靠手感。

### 1.2 几何取值有多散

| 维度 | 不同取值数 | 最杂的几个 |
|---|---|---|
| `padding` | **41 种** | 6px 8px / 3px 8px / 2px 10px / 5px 10px / 9px 12px / 7px 10px / 12px 14px … |
| `margin` | **34 种** | 10px / 12px / 14px / 16px / 8px / 6px 0 / 4px / 2px … |
| `font-size` | **14 种** | 12px(35 次) / 13px(19) / 11px(8) / **12.5px**(6) / 10px(4) / 14px / 15px / 24px / 22px … |
| `border-radius` | **11 种** | 10px / 8px / 6px / 5px / 4px / 3px / 2px / 7px / 12px / 99px / 50% |
| `gap` | **11 种** | 8px / 6px / 10px / 12px / 14px / 3px / 4px / 5px / 2px / 7px / 18px |

几个刺眼的：**`12.5px` 出现 6 次**（12 和 13 之间硬插了一档）；`border-radius` 里有
`3px` / `4px` / `5px` / `6px` / `7px` / `8px` 六连号 —— 相邻两档肉眼几乎无差，
但写代码的人每次都要重新决定一次。

### 1.3 主题切换靠"打补丁"

| 项 | 值 |
|---|---|
| 散落在规则里的硬编码色值 | **36 种** |
| 直接写的 `rgba()` | 7 种（`rgba(0,0,0,.1/.12/.14)` 三个阴影值几乎一样） |
| `:root.dark` 覆盖块 | **11 处**（`.qz-opt.on` / `.qz-tag` / `.df-table tr.on` / `.cell.sev-*` …） |

即"颜色变量"只覆盖了主体，**局部状态色是各写各的**：浅色一套、深色再补一个
`:root.dark .xxx` 块。**再加一个主题（比如护眼绿）就要再补 11 处**。

### 1.4 交互与可达性

| 项 | 值 | 说明 |
|---|---|---|
| `@media` 查询 | **1 处**（`max-width:760px`） | 窗口拉窄基本靠 flex-wrap 硬撑 |
| `:focus` 规则 | **4 处**，且**两种写法** | `.field:focus{border-color}` vs `.cell:focus{box-shadow}` —— 焦点样式不统一 |
| `animation` / `@keyframes` | **0 处** | |
| `prefers-reduced-motion` | **0 处** | |
| `aria-*` 属性（全前端） | **2 处** | 读屏基本不可用 |
| `role=` 属性 | 0 处 | |
| `!important` | 1 处 | 这个很好，说明层叠没失控 |

### 1.5 🔴 internlog 的垂直预算（真机实测，视口 568px）

> 这一条是本次方案里**最有价值的数字**。用 agent-browser 实测 `getBoundingClientRect`。

| 块 | 顶部(px) | 高度(px) |
|---|---|---|
| 顶栏 | 0 | 69 |
| 热力图 | 69 | 209 |
| **效率趋势** | 294 | **234** |
| **工具栏（含「+ 新日志」）** | **540** | 34 |
| 检索条 | 588 | 64 |
| 标签 chips | 662 | 20 |
| 周报面板（展开时） | 692 | 295 |
| **日志列表** | **1001** | 2671 |

**页面总高 3732px，视口 568px。**

两个要命的结论：

1. **日志列表从 1001px 开始** —— 即使周报面板收起（约 -295px），也在 **~700px**，
   **第一屏（568px）里一条日志都看不到**。打开实习日志的第一件事永远是往下滚。
2. **主操作「+ 新日志」在 540px** —— 也在第一屏之外。用户进来想写今天的日志，
   得先滚一下才能找到那个按钮。

**为什么变成这样**：这两批我给 internlog 加了 3 块（效率趋势 / 检索条 / 标签 chips）+
1 块（缺失周报提示），每块单独看都合理，**但没有重新安排整体层级** ——
累积起来把内容挤下去了。这是"局部最优、全局失衡"的典型。

## 2. 方案

### 第一档 · 立竿见影（纯 CSS + 局部 HTML 调整，不动业务逻辑）

#### 2.1 抽设计 token（收益最广，风险最低）

在 `:root` 里补上几何体系，然后**逐步替换**（不要求一次改完 350 条规则）：

```css
:root {
  /* 间距阶梯：只保留 6 档，且都是 4 的倍数 */
  --sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px;
  --sp-4: 16px; --sp-5: 24px; --sp-6: 32px;

  /* 字号阶梯：砍掉 12.5px 这一档，收到 6 档 */
  --fs-xs: 11px; --fs-sm: 12px; --fs-md: 13px;
  --fs-lg: 15px; --fs-xl: 18px; --fs-2xl: 24px;

  /* 圆角：只保留 3 档 + 全圆 */
  --r-sm: 6px;  --r-md: 10px;  --r-lg: 14px;  --r-full: 999px;

  /* 阴影：现在三种 rgba(0,0,0,.1/.12/.14) 几乎一样，合并成两档 */
  --sh-1: 0 1px 2px rgba(0,0,0,.08);
  --sh-2: 0 4px 12px rgba(0,0,0,.12);

  /* 焦点环：一处定义、全站统一 */
  --focus: 0 0 0 2px var(--surface), 0 0 0 4px var(--accent);
}
```

替换策略：**新写的一律用 token；旧的在顺手改到时替换**。不搞一次性大改
（503 行 CSS 全量替换没法保证不出视觉回归）。

#### 2.2 统一焦点环（一行解决两类问题）

```css
:where(a, button, input, select, textarea, [tabindex]):focus-visible {
  outline: none;
  box-shadow: var(--focus);
  border-radius: var(--r-sm);
}
```

- 用 `:focus-visible` 而不是 `:focus` —— 鼠标点击不亮环，键盘 Tab 才亮
- 一处生效，替掉现在那 4 处各写各的 `:focus`
- 顺带把键盘可达性从"看不出来"提到"看得清"

#### 2.3 🔴 internlog 信息层级重排（**本方案的核心**）

目标：**第一屏内必须看到「+ 新日志」和至少一条日志**。

| 改法 | 说明 |
|---|---|
| **① 工具栏提到最前** | 顶栏之下第一块就是工具栏（`+ 新日志` / 生成周报 / 导出 …）。主操作永远在视野内 |
| **② 热力图 + 效率趋势合并成「统计」区，默认折叠** | 两张图共 443px，是最大的两块。折叠后只占一行标题（~34px），**省下约 410px** |
| **③ 折叠状态记进存档** | 存 `internlog:statOpen`（和 `internlog:heat` / `internlog:preview` 同一习惯）。**想看统计的人不用每次展开** |
| **④ 检索条 + 标签 chips 合成一行** | 现在两行 84px → 一行约 34px，**省 50px**。chips 溢出时横向滚动而不是换行 |
| **⑤ 周报面板保持"按需展开"** | 已经是这样了 ✅ 不动 |

**预期效果**（按实测数字推算）：

| | 现在 | 改后 |
|---|---|---|
| 工具栏顶部 | 540 | **69** |
| 日志列表顶部 | 1001（面板收起约 700） | **~210** |
| 第一屏能看到 | 只有两张图 | **工具栏 + 两条日志** |

#### 2.4 统一面板类 `.panel`

现在同类容器有三个名字：`.card`（首页）/ `.note-card`（日志）/ `.df-sec`（缺陷）。
抽一个公共类，各自只保留差异：

```css
.panel { background: var(--surface); border: 1px solid var(--border);
         border-radius: var(--r-md); padding: var(--sp-4); }
.panel + .panel { margin-top: var(--sp-3); }
```

这一档**只做"给现有类补上公共属性"**，不重命名 —— 重命名要动 4 个工具模板，
放到第二档。

## 3. 需要拍板的决策点

### 3.1 CSS 要不要拆出 `index.html`？

**现状**：503 行 CSS 内联在 `index.html` 里，占全文 95%。

**好消息（已实测）**：**拆出去不会打断测试体系** ——
- node 侧 8 个脚本里**没有任何一条断言 CSS 文本**（我 grep 过 `display:` / `border-radius:` / `<style`）
- 真机 6 个脚本用的是 `getComputedStyle`，与 CSS 存放位置无关
- `.sh` 脚本只把 `index.html` 当 URL 用

**坏消息**：`_harness.frontendScripts()`（`_harness.js:34-45`）**只按 `<script src>` 拼源码，
不读 `<link>`**。所以一旦 CSS 变成外链：
- `readFrontend()` 的返回值里就**不再包含 CSS 文本**
- 现在没断，是因为没人断言 CSS；**但这是个埋在未来的坑** —— 哪天有人写一条 CSS 断言，
  会因为"读不到"而静默失败（或更糟：恒真通过）

**建议**：
- **要拆就顺手改 `_harness.frontendScripts()` 让它也读 `<link rel=stylesheet>`**（约 5 行），
  并从 `frontendScripts()` 里分出 `frontendStyles()`。这样测试体系与"CSS 在哪儿"解耦
- 拆的收益：`index.html` 从 529 行回到 ~26 行；CSS 独立文件可折叠、可 lint、diff 清爽
- 拆的成本：CSP 上是安全的（`style-src 'self' 'unsafe-inline'` 已放行同源样式表），
  但要确认 `style-src` 是否允许外链文件 —— 现有策略是 `'self'` ✅ 够用

**我的倾向：拆**。但要与 2.1 的 token 一起做（同一次改），否则要动两次 `index.html`。

### 3.2 图表默认折叠，会不会让人忘了热力图的存在？

有风险。缓解：折叠标题写成 **「统计 · 近 6 个月已写 8 篇 · 平均效率 2.9」**——
把关键数字放进标题栏，**不展开也能看到概况**。这一条建议写进实现要求。

### 3.3 要不要动 `.card`（首页工具卡）的视觉？

首页现在 5 张卡（internlog / sketch / mermaid / quiz / defect）。如果 token 化之后
卡片自动变得规整，就不必单独设计。**建议不动**，避免范围膨胀。

## 4. 验证方式

### 4.1 布局目标要变成断言（这是我的建议，也是本次方案的特点）

2.3 那个目标（"第一屏能看到主操作和至少一条日志"）**是可测的**，
不要只靠肉眼看 —— 加一条真机断言：

```
断言：在 568px 高的视口里
  · 「+ 新日志」按钮的底部 ≤ 视口高度
  · 日志列表顶部 ≤ 视口高度
  · 统计区折叠时，其高度 ≤ 40px
```

放进现有的 `tools/verify-internlog-search.sh`（它已经在测 internlog 的 DOM）。
**这样"布局别退回去"就有人管了** —— 否则下次谁加一块家具，又把它挤下去。

### 4.2 回归

| 层面 | 怎么验 |
|---|---|
| 视觉不回归 | 改完在 5 个工具页各截一张图（真机脚本已有 open/reload 的现成骨架） |
| 功能不回归 | `node tools/verify-all.js --js`（8 个脚本 727 项）+ 6 个真机脚本 218 项 |
| CSS 拆分（若做） | 拆完必须**先**改 `_harness`，再跑全量；并**反向验证**一条 CSS 断言（证明它真的读得到） |
| 主题 | 浅色 / 深色各看一遍（现在 11 处 `:root.dark` 补丁是重点观察对象） |

### 4.3 反向验证（照项目的既有纪律）

token 化之后，抽一条"依赖 token"的断言（例如"主操作按钮在首屏内"），
把 token 值改坏，确认它**真的报 FAIL** —— 否则这条断言就是恒真的。

## 5. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **CSS 全量替换引视觉回归** | 350 条规则，一次性换 token 无法保证不出错 | **只在新写和顺手改时替换**，不做大爆炸式改造 |
| `:focus-visible` 兼容性 | WebView2 基于 Chromium，支持 ✅ | 无风险 |
| 折叠状态存进存档 | 又是一条 `AppStore` 键，导出时会跟着走 | 无敏感性，可接受（和 `internlog:preview` 同类） |
| 拆 CSS 后 `_harness` 没跟上 | 未来 CSS 断言静默失效 | **先改 harness，并做反向验证** |
| 图表折叠后"找不到" | 用户忘了有热力图 | 折叠标题带关键数字（见 3.2） |

---

## 6. 明确不做的事

- **不引 UI 框架 / CSS 预处理器**（Tailwind / Sass）—— 与项目"零构建"的硬约定冲突
- **不做深色主题重做** —— 现有 11 处 `:root.dark` 补丁够用，token 化时顺手收拢即可
- **不动首页 5 张工具卡的视觉**
- **不做移动端适配** —— 桌面单窗口自用，760px 那个断点够
- **不追求 a11y 全面达标** —— 只在第三档补关键交互的 `aria-label`

---

## 7. 建议的执行顺序

```
1. 抽 token（只加变量，不批量替换）          纯 CSS，零风险
2. 统一焦点环                                纯 CSS，一处生效
3. 🔴 internlog 信息层级重排                  本次核心；配一条"首屏可见"断言
4. 补"首屏可见"断言进 verify-internlog-search.sh   + 反向验证
5. 统一 .panel 公共属性                      纯 CSS
── 以上为第一档，做完就该有明显体感 ──
6. 拆 CSS 到 web/css/app.css + 改 _harness   要配套改测试，单独一批
7. 第二档（工具条统一 / 三态组件 / 表格密度）
8. 第三档（响应式 / 动效 / a11y）按需
```

**第 1-5 步不动任何业务逻辑**，风险低、可当天完成；第 6 步要动测试基建，单独走一批。
