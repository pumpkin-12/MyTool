个人工具箱 · Tauri 桌面端迁移方案

把 index.html 单文件网页应用封装为 Windows 桌面应用，数据从浏览器存储迁到本地文件。

2026-09-11 目标平台：Windows 技术选型：Tauri 2 版本锚点：tauri 2.11.x

01结论先行

这次迁移不是重写。现有代码里已经预埋了完整的 Tauri 分支——AppStore 会自动嗅探 window.__TAURI__.core，一旦命中就走 invoke('store_read') / invoke('store_write')；isDesktop 也已经用来决定 Mermaid 优先加载本地文件还是 CDN。缺的只是另一头：Rust 侧的工程、那两条命令、以及配置文件。

所以工作量集中在一件事上：把已埋好的接口接通，并把桌面端特有的三处行为差异收口。

技术栈Tauri 2 稳定线（tauri 2.11.x）。不上 Tauri 3——它目前是 CEF 后端的 early alpha，不适合承载你的唯一数据副本。
是否引入打包器不引入。保持零依赖、无构建，只用 tauri.conf.json 指向前端目录。
体积预期安装包约 3–6 MB，安装后约 10–15 MB；内存占用比浏览器版低。
关键前置本机需装 Rust 工具链（stable）与 tauri-cli；Windows 上需要 WebView2 运行时（Win11 自带，Win10 由安装包补装）。
一句话推荐路径：先做第 0 档拿到「能跑、数据真落盘」的可运行版本，确认无误后再做第 1 档（原生导出、写盘可靠性、数据迁移），第 2 档（图片外置、自动更新、托盘）按需再定。

02现状盘点：已就绪 / 阻塞 / 高危

已经写好了的部分

  • AppStore 三后端探测（Tauri / Electron / 浏览器），接口签名统一，工具代码一行都不用改。
  • 桌面端异步读写的初始化时序已经处理：AppStore.ready 是 Promise，render() 等它，还有 3 秒超时兜底防白屏。
  • 数据 key 命名统一为 toolbox:<tool>:<field>，迁移时好枚举、好排查。
  • Mermaid 的加载顺序已按环境分流：桌面端 [本地, CDN]，浏览器 [CDN, 本地]。

阻塞项（不做就跑不起来 / 丢数据）

编号问题后果处理
B1 vendor/mermaid.min.js 不存在，项目里也没有 vendor/ 目录 断网时 Mermaid 编辑器直接白屏报「库加载失败」 下载 mermaid 11 的 UMD 构建放入 web/vendor/
B2 没有 Rust 侧，store_read / store_write 两条命令不存在 一旦 __TAURI__ 存在，代码就走 native 分支，而命令调不通 → mem 永远是 {}，所有数据静默丢失 新建 src-tauri，实现这两条命令
B3 没有 tauri.conf.json，app.withGlobalTauri 未开 window.__TAURI__ 不存在 → 永远走 localStorage 分支 → 数据存在 WebView 的缓存目录里，清缓存/升级即消失 配置文件里显式设 "withGlobalTauri": true
B4 Windows 上 Tauri 默认用原生 OLE 拖放，会吞掉 WebView 的 HTML5 拖放事件 首页卡片拖拽排序 + 画板拖入图片，两个功能同时失效（表现为禁止光标，dragstart 有反应但 drop 永不触发） 窗口配置设 "dragDropEnabled": false

高危项（不阻塞，但上线后会咬人）

编号问题说明
H1 导出走 <a download> + blob / data URL WebView2 对 blob 下载的处理不受应用控制，可能静默丢弃、或直接落到系统下载目录而不给选择机会。画板 PNG/SVG/JSON、Mermaid SVG/PNG 共 5 处导出都受影响。
H2 persist() 每次 set 全量写盘，且无串行化 多个 invoke 的完成顺序没有保证，快速连续保存存在「后写覆盖先写」的竞态；画板带图后单次 payload 可达数 MB。
H3 native 分支的 AppStore.set 恒返回 true 画板里「内容较大，自动保存失败，请及时导出备份」的提示永远不会触发；磁盘写满、权限异常等情况会完全静默。
H4 画板图片以 base64 内联进 shapes 数组 单张 1600px PNG 压缩后仍有数 MB，进 JSON 再膨胀约 1/3；每次自动保存（400ms 防抖）都要全量 JSON.stringify。
H5 浏览器 → 桌面端没有数据迁移通道 只有画板有 exportJSON；实习日志和 Mermaid 的源码/历史都没有导入功能，换到桌面端等于从零开始。

字段为什么必须这样设
withGlobalTauri: true必填。现有代码靠 window.__TAURI__.core 判断和调用，不开这个全局对象就不存在，而项目没有打包器、也不可能去 import @tauri-apps/api。
dragDropEnabled: false必填。不开会让首页卡片拖拽排序和画板拖图双双失效。这个属性只在 tauri.conf.json 里声明窗口时可靠生效，写到 Rust 的 window builder 里会被忽略。
frontendDist: "../web"相对 src-tauri/ 解析。指向 web/ 而不是根目录，避免把 Rust 工程打进包里。
csp: null先用默认（不注入）。index.html 里有一个巨大的内联 <script> 和大量内联 style，真要收紧 CSP 就得放 'unsafe-inline' 并把 https://cdn.jsdelivr.net 加进 script-src——这是一件独立的事，别和迁移混在一起做。
productName 用 ASCIINSIS 打包的输出文件名会用到它，中文名在部分环境下会出问题。中文显示交给窗口的 title 即可。
identifier反向域名格式，必须全局唯一。它同时决定数据目录位置：%APPDATA%\<identifier>\。

src/lib.rs

use std::fs;
use std::path::PathBuf;

use base64::Engine;
use tauri::{AppHandle, Manager};
use tauri_plugin_dialog::DialogExt;

const STORE_FILE: &str = "store.json";

fn store_path(app: &AppHandle) -> Result<PathBuf, String> {
    let dir = app
        .path()
        .app_data_dir()
        .map_err(|e| format!("无法解析应用数据目录: {e}"))?;
    fs::create_dir_all(&dir).map_err(|e| format!("创建数据目录失败: {e}"))?;
    Ok(dir.join(STORE_FILE))
}

// 启动时一次性读全量。文件不存在不算错误，返回空对象即可。
#[tauri::command]
fn store_read(app: AppHandle) -> Result<String, String> {
    let path = store_path(&app)?;
    match fs::read_to_string(&path) {
        Ok(s) => Ok(s),
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => Ok("{}".to_string()),
        Err(e) => Err(format!("读取存档失败: {e}")),
    }
}

// 先校验再落盘，临时文件 + rename 原子替换，避免写一半断电阻断存档。
#[tauri::command]
fn store_write(app: AppHandle, data: String) -> Result<usize, String> {
    serde_json::from_str::<serde_json::Value>(&data)
        .map_err(|e| format!("拒绝写入：内容不是合法 JSON（{e}）"))?;

    let path = store_path(&app)?;
    let tmp = path.with_extension("json.tmp");
    fs::write(&tmp, data.as_bytes()).map_err(|e| format!("写临时文件失败: {e}"))?;
    fs::rename(&tmp, &path).map_err(|e| format!("替换存档失败: {e}"))?;
    Ok(data.len())
}

// 原生「另存为」。前端把内容转成 base64 传进来，避免字节数组走 JSON 造成体积爆炸。
// 返回空字符串表示用户点了取消。
#[tauri::command]
async fn save_file(
    app: AppHandle,
    file_name: String,
    data_base64: String,
) -> Result<String, String> {
    let bytes = base64::engine::general_purpose::STANDARD
        .decode(data_base64.as_bytes())
        .map_err(|e| format!("内容解码失败: {e}"))?;

    let ext = std::path::Path::new(&file_name)
        .extension()
        .and_then(|e| e.to_str())
        .map(|e| e.to_lowercase());

    let mut dlg = app.dialog().file().set_file_name(&file_name);
    if let Some(ref e) = ext {
        dlg = dlg.add_filter(e.to_uppercase(), &[e.as_str()]);
    }

    // 阻塞式 API 不能跑在主线程，所以这条命令声明为 async
    let Some(picked) = dlg.blocking_save_file() else {
        return Ok(String::new());
    };
    let path = picked.into_path().map_err(|e| format!("目标路径无效: {e}"))?;

    fs::write(&path, &bytes).map_err(|e| format!("写入失败: {e}"))?;
    Ok(path.to_string_lossy().to_string())
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_dialog::init())
        .invoke_handler(tauri::generate_handler![store_read, store_write, save_file])
        .run(tauri::generate_context!())
        .expect("Tauri 应用启动失败");
}

06前端补丁：三处必改

补丁 A · AppStore 写盘串行化 + 失败可见（解 H2 / H3）

把现在的 persist() 换掉，并在 set() 的 native 分支把返回值改成真实的写盘结果：

// 替换原来的 persist()
let writeChain = Promise.resolve();
let writeOk = true;

function persist() {
  if (!T && !E) return;
  const payload = JSON.stringify(mem || {});
  const run = T
    ? () => T.invoke('store_write', { data: payload })
    : () => Promise.resolve(E.writeAll(mem || {}));
  // 串成一条链，保证写盘顺序和调用顺序一致，杜绝后写覆盖先写
  writeChain = writeChain.then(run).then(
    () => { writeOk = true; },
    e => { writeOk = false; showToast('保存失败：' + (e && e.message ? e.message : e)); }
  );
}

同时把返回对象里的 set 改为：

set(key, value) {
  if (native) {
    if (!mem) mem = {};
    mem[K(key)] = clone(value);
    persist();
    return writeOk;            // 原来是恒定的 true
  }
  // 浏览器分支保持原样
  try { localStorage.setItem(K(key), JSON.stringify(value)); return true; }
  catch (e) { return false; }
}
一个诚实的说明：写盘是异步的，所以 set() 的返回值反映的是上一次写盘的结果——失败会在下一次保存时被工具感知到，同时 toast 会立刻弹出。这个「一次延迟」是可以接受的，因为画板的告警本来就是防抖保存后的兜底；要完全同步就得把工具代码改成 async，不值得。

补丁 B · 导出改走系统保存对话框（解 H1）

在全局作用域加一个统一的保存函数，然后把导出调用点都换成它。

function blobToBase64(blob) {
  return blob.arrayBuffer().then(function (ab) {
    const buf = new Uint8Array(ab);
    let s = '';
    const CH = 0x8000;                      // 分块，避免 apply 参数过多爆栈
    for (let i = 0; i < buf.length; i += CH) {
      s += String.fromCharCode.apply(null, buf.subarray(i, i + CH));
    }
    return btoa(s);
  });
}

// 桌面端走原生对话框；浏览器端保持原来的 
async function saveBlob(blob, name) {
  if (window.__TAURI__ && window.__TAURI__.core) {
    const b64 = await blobToBase64(blob);
    const saved = await window.__TAURI__.core.invoke('save_file', {
      fileName: name,
      dataBase64: b64
    });
    if (!saved) { showToast('已取消导出'); return false; }
    showToast('已保存到 ' + saved);
    return true;
  }
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url; a.download = name;
  document.body.appendChild(a); a.click(); a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 2000);
  return true;
}

然后替换这五处调用点：

位置怎么改
画板 exportPNG()c.toDataURL('image/png') 这种 data URL 不能直接转 Blob，改成 await new Promise(r => c.toBlob(r, 'image/png')) 拿到 Blob，再 await saveBlob(blob, name)。
画板 downloadBlob()整个函数删掉，exportSVG / exportJSON 两处调用换成 await saveBlob(blob, name)。
Mermaid download(url, name)同上，改成拿 Blob 后调 saveBlob。exportSVG 里本来就构造了 new Blob([lastGood], ...)，直接传进来即可。
Mermaid exportPNG()它内部用 canvas 转图再 blob，换掉最后那一步的 download 调用。
别忘了给这些函数所在的 mount 加上 async 上下文所需的 await——exportSVG 之类目前是同步函数，改成 async function 后调用点不需要动（返回值没人接）。

07Windows 专项坑位清单

坑表现对策
原生拖放吞事件 拖拽时出现禁止光标，dragstart 触发但 dragover / drop 永不触发。这是 Windows 的 OLE 拖放目标独占导致的，macOS / Linux 不存在 dragDropEnabled: false。注意这是二选一：关掉之后你也拿不到原生文件路径。以后若要做「拖 JSON 进窗口导入」，就得翻回来改用 Tauri 的 onDragDropEvent，两者无法共存
只在配置里生效 dragDropEnabled 写在 Rust 的 window builder 里会被静默忽略 窗口一律在 tauri.conf.json 里声明
WebView2 运行时 Win10 干净系统上双击无反应或提示缺少运行时 由 bundle.windows.webviewInstallMode 决定：downloadBootstrapper（安装时联网下载，包小）或 embedBootstrapper（离线可装，包大）。Win11 自带，没这个问题
字节数组走 IPC 体积爆炸 导出 5 MB 的 PNG，若按 Vec<u8> 传参，JSON 会把每个字节展开成 255, 这样的形式，payload 可能膨胀到十几 MB，界面卡顿 所以 save_file 收的是 base64 字符串而不是数组，Rust 侧用 base64 crate 解码
IPC 参数命名 命令报「缺少参数 file_name」，但前端明明传了 前端 camelCase、Rust snake_case，Tauri 自动转换。两头都写 snake_case 反而会失败
控制台窗口 发布版双击后多一个黑框 main.rs 第一行加 #![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]
剪贴板写图片 画板「复制 PNG」用的是 navigator.clipboard.write([ClipboardItem])，在 WebView 里可能被拒 代码里已有 try/catch 会提示「当前环境不支持」，属于可降级项，不必强求。若确实需要，再加 tauri-plugin-clipboard-manager

08风险与明确不做的部分

明确不做

  • 不上 Tauri 3 / CEF 后端——目前是 early alpha。它的价值是解决跨平台 WebView 渲染差异，而你只面向 Windows，收益为零、风险不小。
  • 不引入 Vite / 打包器——现有代码是精心维护的单文件零依赖结构，引入构建链会把「双击就能跑」这个最大优势弄丢。Tauri 完全不要求前端有构建步骤。
  • 不在这一轮重构画板——画板是三个工具里最复杂的（约 1400 行），迁移期间不动它的内部逻辑，只改导出那几行。
  • 不动 Electron 分支——window.NativeStore 那段探测留着，不删。它是几行死代码，但删了以后如果哪天想试 Electron 就得重写。

遗留风险

  • 单点故障：整个 app 只有一个 store.json。 原子写能防写坏，但防不了误删和磁盘故障。建议第 1 档顺手加「保存时轮转保留最近 3 份备份」——代价很小，收益很大，毕竟画板和实习日志都是无法再生的数据。
  • data-page-node-id 残留——文件里 6 处，是页面编辑器留下的标记，不影响运行，可以在任意一次改动里顺手清掉。
  • 没有版本控制——迁移会新增十几个文件并移动 index.html，强烈建议先 git init 并提交一次现状，否则一旦走岔路就回不去。

09需要你拍板的四件事

#决策点选项与建议
1 应用标识符
bundle.identifier		 反向域名格式，全局唯一，且一旦确定就不要改——它决定数据目录路径，改了等于换个地方存数据。建议 com.<你的名字或缩写>.toolbox。你给一个，我就写进配置。
2 index.html 是否移入 web/ 建议移入（干净、构建快、不会把 Rust 工程打进包）。除非你希望保持「浏览器双击 index.html 也能直接用」这条路径完全不变——那样可以让 frontendDist 指向根目录，但要额外处理打包排除。
3 画板图片是否外置（第 2 档） 如果你画板里经常插图、或者存档已经明显变大，就值得做；如果画板主要用来画图形和写便签，可以无限期跳过。
