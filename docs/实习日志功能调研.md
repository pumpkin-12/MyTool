# 实习日志功能调研：别人都做了什么，我们能抄哪些

> 调研日期：2026-09-21
> 目的：看一眼同类开源项目（尤其「实习/工作日志」这个细分）都有哪些功能，
> 判断哪些值得加进本项目的 **internlog** 板块。
> 结论：**值得抄的有 10 项，其中 6 项是纯前端、当天能做**；但有 1 个硬约束必须先讲清楚。

---

## 0. 先说硬约束：CSP 已经把联网封死了

`tauri.conf.json` 现在的策略是：

```
connect-src 'self' ipc: http://ipc.localhost;
script-src 'self'
```

**桌面端不能访问任何外部服务**（这是 2026-09-20 收 CSP 时刻意做的，与「不联网、不上传」一致）。

这意味着：**下面看到的所有 AI 功能（自动生成周报、润色、自动分类、对话式检索）
在当前架构下一个都做不了**，除非走 Rust 侧转发（前端 → `invoke` → Rust → 外部 API）。
这正是 `docs/AI功能模块方案.md` 里已经规划过的路线。

所以本文档把功能分成两类：
- **不依赖联网** → 现在就能做
- **依赖 AI** → 需要先拍板 AI 方案（Rust 转发 + API Key）

## 1. 调研到的项目（9 个）

| 项目 | 定位 | 最值得看的地方 |
|---|---|---|
| **SpringNote**（Radiant303） | 「懒人实习记录工具」，桌面端 | 功能最全、最对口：AI 整理 + 日/周/月三粒度 + **对话式检索** + 牛马时钟 + 托盘/自启/全局快捷键 |
| **bragdoc**（luissena） | 开发者日记，local-first | **收工五问（End-of-Day Reflection）** —— 用固定问题把零散记录变成结构化自评；按反思维度导出 Markdown 给绩效评审用 |
| **DayCraft**（hxxb） | 智能日报系统 | 日报→周报→月报自动汇总；AI 润色；项目/WBS/甘特图（偏团队，较重） |
| **Lumina-Log**（billchoucn） | 个人工作日志 + AI | AI 内容重构（提关键词/成果/待办/挑战）+ **自动分类**；仪表盘（职能分布饼图、完成率曲线）；Markdown/CSV 导出 |
| **CommitLedger**（flodlol） | 把 GitHub commits 变成工作日志 | **从已有数据自动生成日志**的思路；Markdown/PDF 专业排版导出 |
| **Diary Tool**（RanWurmbrand） | CLI + Excel 日记 | 字段设计值得参考：`日期 / 投入类型 / 描述 / 链接 / 状态 / 影响 / 备注`；按周自动归类 |
| **MoodsNote**（PStarH） | 本地优先日记（Vue+Electron） | **备份带版本号 + 导入冲突预览（合并/替换/跳过）**；情绪趋势曲线；「去年今日」；媒体库 |
| **DailyLogR**（almahfuz777） | Flutter 日记 | 「未编辑窗口」「软删除 + 30 天回收站」等边界处理；streak 风险提醒 |
| **joy-logger / Aura** | 微记录 / AI 日记 | 微记录（240 字）、连续天数徽章、每日提醒；语音输入、情绪分析（偏个人向） |

## 2. 功能全集（按环节归类）

### A. 记录输入
| 功能 | 谁有 | 说明 |
|---|---|---|
| **快速捕获** | SpringNote · bragdoc · joy-logger | 一个输入框随手记，不用先想"算哪天、打什么标签"，之后再整理 |
| **收工引导式复盘** | bragdoc | 固定 5 个问题（今天做成了什么/学到什么/卡在哪/明天做什么…），把空白页变成填空题 |
| 日/周/月三种粒度并列 | SpringNote | 周报月报不是"生成物"，而是可编辑的笔记本体 |
| Markdown + 代码块高亮 | SpringNote · Lumina-Log · bragdoc | 记技术笔记/命令/表格刚需 |
| 语音输入 · 音视频附件 | Aura · MoodsNote | 成本高，收益看人 |
| 待办清单 | Lumina-Log · DayCraft | 日志里带可勾选事项 |

### B. 生成与总结
| 功能 | 谁有 | 说明 |
|---|---|---|
| AI 生成日报/周报/月报 | DayCraft · SpringNote · Lumina-Log | 全部依赖 LLM |
| AI 润色（口语→书面） | DayCraft · Lumina-Log | 依赖 LLM |
| **AI 自动分类打标签** | Lumina-Log | 依赖 LLM；手工版 = 关键词规则映射 |
| AI 提取关键词/成果/待办/挑战 | Lumina-Log | 依赖 LLM |
| **自动补齐缺失报表** | SpringNote | 启动时按已有日报补出没写的周报/月报（**这一步纯逻辑，不需要 AI**）|

### C. 检索
| 功能 | 谁有 | 说明 |
|---|---|---|
| 关键词检索 | 大家都有 | 我们已有 |
| **对话式检索** | SpringNote「回忆书」· Lumina-Log | 真对话要 LLM；**降级版**：关键词 + 时间 + 标签的结构化过滤 |
| 标签/分类/日期范围过滤 | bragdoc | 我们只有关键词，**缺结构化过滤** |
| 「去年今日」回顾 | MoodsNote | 纯前端，成本极低 |

### D. 可视化
| 功能 | 谁有 | 说明 |
|---|---|---|
| 贡献度热力图 | 大家都有 | 我们已有，且**比多数项目更细**（按效率上色 + 自定义区间） |
| 效率/情绪趋势曲线 | DailyLogR · MoodsNote | 我们现在只有"平均效率 N"，**没有趋势线** |
| 标签/职能分布饼图 | Lumina-Log | 我们只有按标签分组统计 |
| **投入分布（工时占比）** | SpringNote「牛马时钟」 | 我们完全没有 |
| 连续天数 + 里程碑徽章 | joy-logger · SpringNote | 我们统计行里有"连续 N 天"，**没有成就感** |

### E. 输出
| 功能 | 谁有 | 说明 |
|---|---|---|
| Markdown 导出 | bragdoc · Lumina-Log · CommitLedger | 我们只有"复制到剪贴板" |
| CSV/Excel 导出 | Lumina-Log · MoodsNote | **我们已有 `xlsx.full.min.js`，成本极低** |
| PDF 导出 | CommitLedger · MoodsNote · Aura | 交周报大概率要 |
| **Word 导出** | 少见（多是 PDF） | **但这是我们的真实交付格式**（公文/Word）|
| **按维度分组的自评文档** | bragdoc | 给绩效评审用的结构化导出 |

### F. 数据
| 功能 | 谁有 | 说明 |
|---|---|---|
| 本地优先存储 | 全部 | 我们已有（且更强：分键 + 资产外置） |
| JSON 全量备份/导入 | 全部 | 我们已有 |
| **备份带版本号 + 冲突预览（合并/替换/跳过）** | MoodsNote | 我们现在是"按 id 去重"，**比它糙** |
| 一键同步网盘 | Diary Tool（Google Drive） | 与"不联网"冲突，跳过 |

### G. 桌面端体验
| 功能 | 谁有 | 说明 |
|---|---|---|
| **托盘 / 开机自启 / 全局快捷键** | SpringNote | 我们的 README 待办里已经有这项 |
| **桌面小组件（计时器 + 今日收益）** | SpringNote | 有趣但偏玩 |
| **每日提醒通知** | joy-logger · DailyLogR | 促使用户每天写 |
| PWA/离线 | DayCraft | 我们是原生桌面，不需要 |
| 软删除 + 回收站 | DailyLogR · MoodsNote | 防手滑，值得 |

## 3. 对照现状：我们其实不算落后

| 维度 | 我们的状态 |
|---|---|
| ✅ 已经不输 | 本地优先存储（分键 + 资产外置，比多数项目扎实）、热力图（按效率上色，比他们的"有没写"更细）、配图、标签、备注、周报按标签汇总、JSON 备份 |
| ❌ 明显缺 | 结构化检索（只能关键词）、趋势可视化、任何表格/文档导出、待办、工时、提醒、回收站 |

---

## 4. 建议：值得加的 10 项，分三档

### 第一档 · 纯前端，当天可做（我推荐先做这档）

| # | 功能 | 抄谁 | 为什么值得 |
|---|---|---|---|
| 1 | **Markdown 渲染 + 代码块高亮** | SpringNote / Lumina-Log | 记 MES 排障、SQL、命令、步骤时，纯文本很难读 |
| 2 | **结构化检索** | bragdoc | 现在只能搜关键词。加「标签 × 日期范围 × 效率」过滤，成本很低 |
| 3 | **导出 xlsx（台账）** | Lumina-Log | `xlsx.full.min.js` 已在 `web/vendor/`，几乎零成本 |
| 4 | **导出 Word / Markdown 周报** | bragdoc / CommitLedger | 你的真实交付是 Word 公文。生成 HTML/Markdown 再套你已有的转换流程最省事 |
| 5 | **收工引导式复盘** | bragdoc | 空白页变填空题，专治"不知道写什么"。就是几个固定问题 + 一键插入 |
| 6 | **快速捕获** | SpringNote | 随手记一句先放着，之后再归到某天/打标签。降低记录摩擦 |
| 7 | **「去年今日」/ 随机回顾** | MoodsNote | 纯前端，几行代码，但能让你真的回看旧日志 |
| 8 | **待办区块** | Lumina-Log / DayCraft | 日志里写"下次要做"，汇总页看未完成项 |
| 9 | **效率趋势曲线** | DailyLogR | 现在只有"平均效率 N"，看不出走向 |
| 10 | **回收站（软删除）** | DailyLogR / MoodsNote | 防手滑。现在删日志是直接删 |

**其中我最推荐先做 1 / 3 / 4 / 5** —— 分别解决「技术笔记不好读」「没有台账」「交付格式不对」「不知道写什么」四个真实痛点，且都不需要联网、不需要改 Rust。

### 第二档 · 需要动 Rust 或加依赖

| # | 功能 | 前置条件 |
|---|---|---|
| 11 | **AI 生成周报/月报 + 润色** | 必须先拍板 `docs/AI功能模块方案.md`（Rust 转发 + API Key）。**价值最高，但也是唯一需要外部服务的一项** |
| 12 | **托盘 / 开机自启 / 全局快捷键** | Rust 改动，README 待办里已有 |
| 13 | **每日提醒** | 托盘 + 通知，顺带一起做 |
| 14 | **备份格式加版本号 + 导入冲突预览** | 纯前端，但要改 `importAll` 契约；MoodsNote 的「合并/替换/跳过」值得抄 |
| 15 | **工时计时器** | 纯前端可做，但要想清"记工时"会不会变成负担 |

### 第三档 · 不建议抄

| 功能 | 为什么不做 |
|---|---|
| 项目管理 / WBS / 甘特图 / 里程碑（DayCraft） | 那是团队项目管理系统，对单人日志过重 |
| 多人协作 / 云同步 / 社区分享 | 与「本地优先、不联网」直接冲突 |
| 从 GitHub commits 生成日志（CommitLedger） | 你的主业是工厂 MES/IT，不是每天写代码 |
| 语音输入 / 音视频附件 | 成本高，日记场景收益不确定 |
| AI 情绪分析 | 你已经有效率 1~5 评分，够用 |
| PWA / 移动端 | 原生桌面应用，不需要 |

---

## 5. 一句话总结

**同类项目比我们多的，主要就三块：AI 生成、结构化检索、导出。**
第一块被 CSP 挡着（要先拍板 AI 方案）；后两块纯前端就能补，而且成本都不高。
我们已有的「按效率上色的热力图 + 分键存储 + 资产外置」反而是这批项目里做得更细的。

建议顺序：**先做第一档的 1/3/4/5**，再谈 AI。
