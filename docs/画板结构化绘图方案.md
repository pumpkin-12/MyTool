# 画板「结构化绘图」改造方案

> 编写日期：2026-09-17
> 目标：让画板能画**流程图 / 架构图**（不追求「和 draw.io 一样」，追「够用」）
> 路线：**A · 手写补齐**（不引入 maxGraph 引擎）
> 状态：**待你选档后实施**

---

## 1. 结论

| | |
|---|---|
| 目标定位 | 结构化图（流程图、架构图、拓扑图） |
| 路线 | A：在现有画板模块上增量补，**不引入外部引擎** |
| 核心洞察 | 决定「像不像 draw.io」的只有 **3 件事**：图形内能写字、锚点连线、形状库。其余都是锦上添花 |
| 工作量 | 第一档 ≈ 1~2 天（含真机验证）；第二档 ≈ 1 天；第三档另议 |

### 为什么不走 maxGraph

查了 `@maxgraph/core`（mxGraph 的官方后继，draw.io 同一血脉）的 npm 元数据：

```
版本 0.24.0 · 许可 Apache-2.0 · 解包 7.1 MB · 1097 个文件
main: lib/cjs/index.js · module: lib/esm/index.js · type: module
```

**只发 ESM + CJS，没有单文件 UMD**。要用就得先离线 esbuild 打一个 IIFE bundle 塞进 `web/vendor/`。

代价不是那点体积，而是：**等于重写整个画板模块**（现在 1784 行全部作废），
自定义的便签、画笔、迷你地图、对齐参考线都得按它的模型重做。
而且我**没有验证过**它在 Tauri/WebView2 下真能跑 —— 这是未知风险。

**判断：先手写补齐。真不够用再上引擎也不迟**（届时第一档的成果也不算白做，至少明确了需求）。

## 3. 第一档：让它真的能画流程图（核心，建议先做）

### 3.1 图形内文字（label）

- 给 `rect` / `ellipse` / `diamond` / `roundrect` 加 `text` 字段
- **双击图形进入编辑**，复用现有编辑机制（第 2718 行 `editor.value = s.text`）
- 居中渲染 + 自动换行 + 垂直居中（复用现有 `wrapText`，第 3343 行）
- 文字颜色：深色主题下自动用亮色
- 空标签不显示占位

**注意**：canvas 渲染与 SVG 导出**两条路都要改**，否则导出图里没字。

### 3.2 形状库（第一档先加 2 个）

| 新形状 | 用途 | 说明 |
|---|---|---|
| `diamond` 菱形 | 判断 | 快捷键 `D` |
| `roundrect` 圆角矩形 | 起止 / 通用处理 | 快捷键 `U` |

每个新形状要改 **5 处**：工具按钮、mousedown 创建、canvas 渲染、SVG 导出、命中测试。
（命中测试建议用「点在包围盒内」的宽松判定，菱形不做精确多边形判定 —— 够用优先。）

### 3.3 🔴 锚点连线（这是「像 draw.io」的关键）

**数据模型**

```js
// 现在的箭头：{ id, type:'arrow', x1,y1, x2,y2, color, size }
// 改造后：两端各自「要么接图形锚点，要么是自由坐标」
{
  id, type: 'arrow', color, size,
  from: { id: 's1', side: 'e' } | null,   // 接图形：side ∈ n/e/s/w
  to:   { id: 's2', side: 'w' } | null,
  x1, y1, x2, y2                          // 仅当对应端为 null 时使用
}
```

- 🔴 **端点坐标不落盘，渲染/命中时实时从图形 bbox 推算**。
  存死坐标的话，图形一移动连线就脱节 —— 这是这类功能最常见的坑。
- 旧数据没有 `from`/`to` → `null` → 退化成自由箭头，**天然兼容，不需要迁移**。

**交互**

1. 用箭头/直线工具从图形**边上**起笔 → 该端吸附到最近锚点
2. 起点/终点靠近图形时，显示 4 个锚点小圆并**高亮命中的那个**
3. 拖动图形 → 相连的连线**自动跟随**
4. 拖动连线端点 → 改接到别的锚点（拖到空白处则变成自由端点）
5. 删除图形 → **连线不删**，退化成自由端点（更安全，不会一下子丢一堆线）

**锚点位置**：先做 4 向（n/e/s/w，取包围盒四边中点），够用。8 向留到第二档。

### 3.4 网格 + 吸附

- 画布背景 20px 网格，工具栏加开关
- 新建/移动时吸附到网格（可关）
- 与现有「对齐参考线」共存：网格吸附先算，参考线吸附优先级更高

## 5. 第三档：模板与互通（视需要）

- 形状库面板（分类 + 可搜索，类似 draw.io 左侧栏）
- 模板：空白流程图 / 三层架构 / 部署拓扑

## 6. 明确不做

- 多人实时协作、云存储
- maxGraph 全量迁移（除非第一档做完仍不满意）
- 精确的多边形命中测试（菱形判定用包围盒即可）
- 自由手绘的曲线平滑 / 压感

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| canvas 与 SVG 导出两条渲染路径不同步 | 新形状/连线**必须同时改两处**；验证脚本要断言 SVG 里也有对应元素 |
| 连线端点实时推算 → 图形移动时性能 | 现在图形量级很小（几十个），先不做索引优化；出现卡顿再说 |
| 旧存档兼容 | 新字段全部可选 + `\|\| null` 兜底，**不做数据迁移** |
| 图形删除后连线成孤儿 | 退化为自由端点（可见、可删），不静默丢弃 |
| 改坏现有画板功能 | 第一档同步建 `tools/verify-sketch-*.sh`（真机浏览器），覆盖：新形状渲染、锚点吸附、连线跟随、SVG 导出含新元素、旧数据兼容 |
| `index.html` 继续膨胀 | 第一档预计 +600~900 行 → 约 6500 行，**仍在 8000 警戒线内** |
